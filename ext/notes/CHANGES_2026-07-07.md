## 1. Sweep optimization (ehp-core/src/interpage.rs) — the big one

**Before:** `sweep <r>` ran 2×U independent trials; each trial re-turned
thousands of degrees (`get_tb`) from scratch, deep-cloned the target SATPage,
rebuilt by_n/by_ns/stale-block indices by scanning all page keys/blocks, and
deep-cloned/dropped all TurnedBidegrees. ~85% of time was allocator churn.
t=50/MAX_R=6 sweep: **749.6s**. t=100 extrapolated to days.

**After:** **9.9s** at t=50 (~75×); t=70/MAX_R=7 = 2492 trials in minutes.
[PARITY] [ADVERSARIAL] Components (each separable):

a. **Filter reorder** — product-candidate filters (max_s / unit-degree /
   recomputable / shifted-present / polygon) run BEFORE the needed-turned-
   degree collection (`candidates.retain(..)` in `build_overlay_page`), so
   rejected triples never cost a page turn. This was the single biggest win.
   Accepted math delta: trials no longer *incidentally* detect d∘d≠0 at
   degrees only rejected candidates needed — detection now matches the
   canonical triple enumeration exactly (reviewed; the parity runs at t=50
   and the t=70 forced value were identical).
   *Revert:* move the retained predicates back into the product apply-loop
   after `tb_at` lookups and rebuild `needed` from ALL candidates.

b. **`TbCache`** — get_tb results for the stock first page + base result,
   precomputed in parallel at sweep start, then read lock-free. Trials
   consult it only on the FIRST page step and only at degrees whose
   rep(t)/rep(t_in) is not in the trial's dirty set (degrees of assumed +
   learned vars — provably the only places the trial's result differs;
   see the invariant writeup in SESSION_HANDOFF §July 7). Do NOT reintroduce
   a lazy RwLock version — it was 3× slower under rayon contention.
   *Revert:* pass `None` instead of `Some(&cache)` in `trial_error_sweep`
   (one line) — trials then always compute fresh, exactly the old semantics.

c. **`SweepCache` / `PageIndex` / `SourceIndex`** — per-sweep precomputed
   stock-page indices (partner lists by n / n+s; keys, naturality squares,
   product blocks inverted by stable rep), consumed with per-trial
   added/removed dimension deltas. GOTCHA: partner lookups are ITERATOR
   CHAINS on purpose; building filtered Vec copies per lookup was a 2.7×
   regression at t=70 (invisible at t=50).
   *Revert:* same one-liner as (b) — with no cache, `build_overlay_page`
   builds a local PageIndex per call (slower for bulk try_diffs but same
   results).

d. **Arc'd turned data** — `LocalTurn::tbs` and the overlay tbs maps hold
   `Arc<TurnedBidegree>` (was owned values; cloning/dropping them was ~20%
   of sweep time). *Revert:* mechanical de-Arc; no semantic content.

e. **`try_diffs_with_cache`** — public wrapper; plain `try_diffs` unchanged
   behavior (cache=None). REPL `try` uses the uncached path.

## 3. build_pairs removal (io.rs, pageturning.rs, ehp-server/src/lib.rs, ehp-cli/src/main.rs)

**Before:** `SATPage.pairs` (degree → partner-degree list) was built on E2
load AND after every page turn — ~13% of startup CPU, single-threaded.
**After:** all `build_pairs()` calls removed; field kept + documented as
unpopulated. [PARITY]

**Evidence it was safe:** `grep -rn '\.pairs'` across all crates — the ONLY
reader is `diag_clone_cost.rs` (a size-measuring diagnostic). The Leibniz
enumeration in `build_constraint_system` iterates its own s/f/n loops with
data-driven bounds (`max_data_n`) and NEVER consulted `page.pairs`; removing
it changed no constraint. Parity at t=50 byte-identical post-removal.

**USER CONCERN (recorded):** the intuition "pairs makes Leibniz cheaper by
restricting which pairs are checked" describes what pairs SHOULD do, not
what the Rust code ever did. FUTURE WORK (do not revert; implement instead):
gate the Leibniz pair enumeration with a precomputed nonzero-product index
(revive `pairs` as an actual consumer-driven index) — today's diagnostics
show ~95k candidate pairs scanned per variable neighborhood with the vast
majority guard-rejected; a product-support index could cut constraint
generation dramatically. If implemented, benchmark at t≥70 (see §10).

*Revert (if ever needed):* re-add `page.build_pairs()` at io.rs (after
load), pageturning.rs `build_page_from_turned` (before `next`), lib.rs
(both load sites), ehp-cli (both sites). Costs ~13% startup for no current
consumer.

## 4. Leibniz hoisting (ehp-core/src/constraints.rs) — REVERTED, net zero

An optimization of `make_leibniz_constraint_single` / `matrix_mult_right` /
`equals_rel` was landed and then **fully reverted** the same day: correct
([PARITY]) but a ~10× t=70 startup regression — the workload is dominated by
pairs that abort via `skip()` after near-zero work, and the rewrite hoisted
matrix construction above those fail-fast exits. constraints.rs is verbatim
back to its pre-today state. Full mechanism analysis: memory note
`ehp-perf-benchmark-at-scale.md`. Nothing to revert; the lesson is §10.

## 5. REPL changes (ehp-server/examples/ehp_chart.rs)

**Before/after per feature:**

a. **WASD unification** — stem charts were a/d=stem, w/s=page; split-screen
   map views were w=source+. Now everywhere: w/s = dimension-like axis −/+
   (sphere n / stem k, P-map step-2 kept), a/d = page −/+. Sphere charts
   already matched (unchanged). *Revert:* swap the STEMNAV up/down/left/right
   JSON assignment and the map-view NAVDATA w/s direction back.

b. **Stem chart titles** — were falling through to a wrong "E_2(S^2)"
   default; now KaTeX `E_r(π^k)` via a stem-filename branch in
   `generateTitle()` (in the SHARED repo template — see §7).

c. **Auto-regen of affected charts** (user-requested "no shortcut"):
   `cascade_resolve` returns `CascadeOutcome { deduced, affected_degrees }`;
   `regen_affected_charts` re-exports CSVs and regenerates ONLY the affected
   sphere/stem charts after every add/zero/toggle/remove/undo/interpage
   (~1–3s per add; >80-chart cascades skip with a `regen` hint).
   **Before:** live updates only rewrote CLASSDIMS dimension counts and the
   JS faded the LAST node index at a bidegree — displaying the wrong class
   as dead when the quotient killed a different basis vector (engine was
   always correct; display lied). *Revert:* call sites drop the
   `regen_affected_charts` call — the CLASSDIMS fade shortcut remains as
   the fallback path and takes over again.

d. **UNSAT transparency** — `PageState.unsat_reason` set at every result
   assignment; `sweep`/`try` explain missing results ("E_2 re-solve was
   INCONSISTENT after `add …` — `undo` to restore"); `interpage try`
   announces skipped pages; propagation-truncation notes. **Before:** bare
   "E_r has no solve result", silent skips. [USER: confirmed via the
   remove-d2 recovery]

e. **Targeted undo** — `undo <r> <n> <s> <f> <row> <col>` reverts the most
   recent matching mutation; argless `undo` = old LIFO pop, unchanged.
   **Before:** args were silently ignored (popped an unrelated mutation).

f. **Auto-bisect on INCONSISTENT batches** — one re-solve per mutation
   against the pre-batch snapshot; names individually-impossible mutations
   (or the first tipping one), stores the culprit in unsat_reason, prints
   undo recovery + engine-bug note. Batch stays applied (no auto-undo).
   **Before:** "E_4: INCONSISTENT" with no culprit (user bisected by hand).

## 9. New diagnostic/verification tooling (ehp-server/examples/)

- `diag_sweep_verify.rs` — THE parity harness: prints every trial's full
  sorted learned-diff list; diff two builds' logs for byte-identical
  behavior. Run before/after ANY change to the trial path.
- `diag_leibniz_var.rs` — for a differential (DIAG_N/S/F/R): why is it
  undetermined? Enumerates all candidate Leibniz pairs with per-guard
  reject reasons, h_i-pair flagging, counterfactual un-exclude + re-solve.
- `diag_unsat_cert.rs` — UNSAT certificate extraction (in flight, §8b).

## 10. Operating lessons (also in memory + SESSION_HANDOFF)

- Benchmark ANY perf change on a real t≥70 workload before shipping; t=50
  parity + unit tests catch correctness only. Leibniz generation is
  fail-fast-dominated: never add work above its skip() exits.
- Parity harness for every trial-path change; kill-switch env flags for
  every semantics-adjacent engine change.
- `sample <pid>` a stuck REPL before theorizing (97% single-core = serial
  phase); inlining smears line attribution — confirm by mechanism.
- Multi-core agents/builds and timing benchmarks must not share the machine.
